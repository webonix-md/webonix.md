# WEBONIX7 — дизайн-система

Тёмный techno-brutalism / scitech сайт для двуязычного (RO/RU) B2B веб-студии
в Молдове. Дизайн-система и стили унаследованы от [webonix4](../webonix4/DESIGN.md),
структура и контент (разделы, тексты, цены, формы) перенесены из [webonix2](../webonix2/index.html)
и переведены на RO. Визуал — реальные фото Pexels по теме веб-разработки/IT/B2B
(не архитектура/брендинг, как в источнике дизайн-системы).

## Структура

```
webonix8/
├── index.html                  ← главная (лендинг)
├── pages/
│   ├── services.html           ← услуги и цены
│   ├── logo.html                ← логотип и фирменный стиль
│   ├── audit.html               ← бесплатный аудит
│   └── contacts.html            ← контакты
├── DESIGN.md                    ← этот файл
└── design-system/
    ├── tokens.css                ← токены + все компоненты (webonix4 + расширения ниже)
    ├── core.js                   ← JS-логика (курсор, часы, i18n, scrollspy, форма, мобильное меню)
    └── template.html             ← пустой шаблон новой страницы (из webonix4, не адаптирован)
```

**Как сделать новую страницу:** взять любую существующую страницу из `pages/`
как основу (в ней уже есть `.site-nav`, HUD, `#layerNav`, подключение
`tokens.css`+`core.js`), скопировать, поменять `<title>`, секции и
`data-layer`/`data-label-ro`/`data-label-ru`.

## Отличия от webonix4 (важно!)

webonix4 — это одностраничник без сквозной навигации между страницами (HUD
виджеты `#hud-status`/`#hud-lang` сидят по фиксированным углам). webonix8 —
сайт из 5 страниц, поэтому:

1. **`.site-nav`** — новый фиксированный верхний бар (56px), заменяет
   `#hud-status` и `#hud-lang` из webonix4. Содержит лого-ссылку на главную,
   ссылки на все 5 страниц (с `.active` на текущей), телефон-ссылку и
   переключатель языка. На `≤1150px` превращается в гамбургер +
   полноэкранное выпадающее меню (`.nav-toggle` + `.site-links.open`,
   логика в `core.js: initNavToggle()`). Порог поднят с 900px, т.к. при
   увеличении `--fs-label`/добавлении телефона полная навигация переставала
   помещаться на ширинах 900–1150px. Ссылка `.phone-link` внутри
   `.site-links` — дубликат телефона из `.site-status` специально для
   выпадающего меню (`.site-status` скрывается на `≤1150px`, иначе
   телефон был бы вообще недоступен на этих ширинах). `.site-logo` — не
   текст, а inline SVG (кружок+«W»+точка+«ebonix»), перекрашенный в
   `var(--cyan)`/`var(--bg)` вместо оригинального сине-фиолетового
   градиента лого; копировать один в один, как остальной `.site-nav`.
   **Копировать один в один** на каждую страницу, поправляя только `href`
   (на главной — прямые пути `pages/...`, на подстраницах — `../index.html`
   и соседние `service.html`/`logo.html`/... без `pages/`) и `.active`.
2. `body{padding-top:56px}` — компенсирует высоту `.site-nav`.
3. `#hud-loc` и `#hud-clock` остаются как в webonix4 (нижние углы).
4. Каждая страница — свой набор `section[data-layer]` и свой `#layerNav`
   (scrollspy пересчитывается на каждой странице заново, ничего общего
   между страницами хранить не нужно — `core.js` читает секции текущего DOM).
5. Все секции используют либо `.hero-section` (первый экран, часто
   `.inner.centered` для страниц-подстраниц без сплит-фото), либо голую
   `<section>` с `.section-head` — сплит-фото-хиро на два столбца, как было
   в оригинальном webonix2, не воспроизводился (не входит в компонентный
   набор webonix4); вместо этого везде используется `.text-photo-grid`
   (см. ниже) для паттерна «фото + текст».

## Новые компоненты (добавлены в `tokens.css`, после блока FOOTER)

Общее для всех: `background:var(--line)` на гриде + `background:var(--bg)`
на ячейках → тонкие 1px разделители без лишних `border`, как в `.cards`
из webonix4.

| Класс | Назначение |
|---|---|
| `.stats-row` / `.stat` | Метрики в hero (например `4–6 / SĂPT. / TERMEN...`). |
| `.hero-badge`, `.slots-badge`, `.chip`, `.chip-row` | Мелкие бейджи/чипы в hero (статус, urgency-слоты, список услуг). |
| `.cta-row`, `.cta.outline` | Несколько CTA-кнопок рядом; `.outline` — прозрачный вариант с рамкой. |
| `.nav-cards` / `.nav-card` | Текстовые карточки-навигация (без фото), 3 колонки. |
| `.advantages` / `.advantage` | Список преимуществ, 2 колонки, номер + текст. |
| `.timeline` / `.timeline-step` | Горизонтальный процесс в 4 колонки (этапы, сроки, % оплаты). |
| `.stage-grid` / `.stage-card` | То же самое, но 3 колонки для процессов из 6+ шагов. |
| `.audit-grid` / `.audit-item` | Нумерованная сетка 3×2 (что входит в аудит, стек технологий). |
| `.fear-list` / `.fear-item` | Список «типичных страхов» с `✕`. |
| `.faq-list` / `.faq-item` / `.faq-q` / `.faq-a` | FAQ в терминальном стиле (`> ВОПРОС`). |
| `.package-grid` / `.package-card` (`.featured`, `.package-badge`) | Тарифные карточки (цены), средняя может быть выделена рамкой `--cyan` + бейдж. |
| `.guarantee-grid` / `.guarantee-col` (`.included`/`.not-included`) | Две колонки «входит/не входит» с `✓`(mint)/`✕`. |

| `.text-photo-grid` (+`.reverse`) | Универсальный паттерн «фото + текст», 2 колонки; `.reverse` меняет фото на правую сторону. |
| `.terminal .radio-row` | Радио-кнопки мессенджера внутри `.terminal`-формы. |

## Шкала шрифтов (`:root`, верх `tokens.css`)

```css
--fs-h1:    clamp(2.2rem, 5.5vw, 5rem);  /* .hero-title */
--fs-h2:    clamp(1.8rem, 4vw, 4rem);    /* .section-head h2 */
--fs-label: 12px;                        /* мелкие mono-лейблы (badge/chip/label-mono/...) */
--fs-body:  16px;                        /* обычный текст (p, .sub, .hero-sub, ...) */
--fs-stat:  32px;                        /* крупные цифры (stats-row/audit-num/payment-num/package-price) */
```

Меняете размер целой категории текста в одном месте — правите переменную,
эффект применяется везде, где она подставлена через `var(--fs-...)`.
**Не входят в шкалу** (сознательно, у них другая роль): заголовки карточек
h3/h4 (`.nav-card h3`, `.advantage h4` и т.п. — отдельный уровень между
label и h2, фиксированные 14–17px), и «системный хром» — HUD-виджеты,
курсор, футер, `.lang-switch`, `.package-badge` (это телеметрия/декор,
не читаемый контент, им положено быть мелкими).

**Важно про фон блюра (`filter:blur(...)`)**: если внутри блюрного блока
нужна читаемая подпись (например «превью отчёта», «образец договора»),
блюр-фон и подпись должны быть **разными** элементами (фон — абсолютно
спозиционированный слой с `filter`, подпись — соседний слой поверх), иначе
`filter` на родителе размывает и текст-потомок тоже. См. `.report-preview`
в `pages/audit.html`.

**Важно про CSS-специфичность i18n**: правило скрытия языка —
`html[data-lang="ro"] .ru{display:none}` — имеет специфичность (0,0,2,1).
Если новому компоненту нужен стиль на обёртке текста, стилизуйте класс
`.i18n` (или свой собственный класс) на этой обёртке, а не голый тег
(`span`/`li`/`div`) в связке ровно с 2 классами-предками — иначе при
случайном совпадении специфичности порядок объявления в файле решает,
кто победит, и один язык может «пролезть» поверх другого одновременно
с переводом (баг воспроизводился на `.stats-row .stat span` — исправлено
на `.stats-row .stat .i18n`).

**Важно про `aspect-ratio` внутри `<section>`**: `section` в этой
дизайн-системе — `display:flex;flex-direction:column`. Пустой `div` с
`aspect-ratio` и `max-width`, но без явного `width`, может посчитать
высоту от auto-контента (=0) и потом вывести ширину из этой нулевой
высоты через сам aspect-ratio → элемент схлопывается. Всегда добавляйте
`width:100%` на такие обёртки (см. `.report-preview` в audit.html).

## Остальное — как в webonix4

Токены цвета/типографики, механизм RO/RU (`.i18n`/`.ro`/`.ru` + `WEBONIX.switchLang`),
`layerNav`-scrollspy, курсор, часы, terminal-форма, голос копирайта
(короткие императивные заголовки CAPS LOCK без подчёркиваний, обычная
пунктуация в подзаголовках, никаких эмодзи и lorem ipsum) — без изменений,
см. [webonix4/DESIGN.md](../webonix4/DESIGN.md). **В отличие от webonix4**,
подчёркивания вместо пробелов в заголовках/лейблах (`SISTEM_DE_IDENTITATE`)
здесь не используются — везде обычные пробелы (`PROTOCOL LANSARE`).

**Одно уточнение по длинным заголовкам**: `overflow-wrap:break-word` на
`h1,h2,h3` может сломать слово прямо посреди буквы, если строка не
помещается в узкую колонку (особенно в 3-колоночных `.nav-cards`/`.audit-grid`
и в 2-колоночных hero на подстраницах). Держите заголовки короче (2–3 слова),
длинные уточнения (сроки, цифры) выносите в обычный `.sub`-подзаголовок под ними.
